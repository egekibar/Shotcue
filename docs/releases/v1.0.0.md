Shotcue 1.0.0 is the first public release of Shotcue, a macOS menu-bar app that turns a screenshot and a short note into a task for Claude Code.

## What it does

- **Capture a region.** Press the global hotkey (shown and changeable in Settings → Genel → "Kısayol") and drag over any part of the screen with macOS's own selection tool.
- **Say what you want.** A quick panel opens with the capture. Type a note or record one: voice notes are transcribed on your Mac with WhisperKit, in Turkish by default (English selectable), so the audio never leaves the machine.
- **Keep a library.** Captures are grouped by project, and a project is a folder on disk. Search, sort, filter by status, merge several captures into one task or move them between projects.
- **Hand it to Claude Code.** Send a task to headless Claude Code (`claude -p`) in the project folder right away, at a date and time you pick, or with the project's daily queue. Shotcue streams the live log, shows the summary, turns and estimated cost, and notifies you when the run ends.
- **Review and continue.** See what a run changed in the in-app git diff, and continue the same Claude Code session in Terminal or in Claude Desktop.

The UI is in Turkish (Settings is "Ayarlar"); where it helps, this page quotes the Turkish label.

## Requirements

- macOS 26 or later.
- A Mac with Apple Silicon.
- Claude Code CLI installed and logged in with a Claude subscription. Shotcue runs `claude` with that login and never uses an API key (it removes `ANTHROPIC_API_KEY` from the run environment). It looks for `claude` in `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin` and your login shell's `PATH`; you can also set the path in Settings → Claude.
- Optional, only for voice notes: the WhisperKit speech model, a one-time download of about 1.6 GB that starts only after you confirm it (in Settings → Ses, or from the quick panel). Typed notes work without it.

## Install

1. Download `Shotcue-1.0.0.dmg` below, open it and drag **Shotcue** onto **Applications**.
2. This build is not notarized by Apple, so macOS blocks its first launch. Allow it in one of two ways:
   - Open Shotcue once and dismiss the warning. Then open **System Settings → Privacy & Security**, scroll down to **Security**, click **Open Anyway** next to the message about Shotcue and confirm.
   - Or remove the quarantine attribute in Terminal:

     ```sh
     xattr -dr com.apple.quarantine /Applications/Shotcue.app
     ```
3. On first launch Shotcue asks for **Screen Recording** (required, for captures) and **Microphone** (only for voice notes). macOS may ask you to reopen Shotcue after you grant Screen Recording.

Shotcue lives in the menu bar; open the library and Settings from its menu.

## Safety

Shotcue lets Claude Code change your code without asking. Read this before your first run.

- **Implement** mode (Uygula) runs Claude Code with full permissions (`--permission-mode bypassPermissions`) inside the project folder you chose: it edits files and runs commands without asking for approval. **Analyze** mode (Analiz) is read-only. You can lower Implement's permission mode to `acceptEdits` in Settings → Claude.
- Every project has two optional safety nets, both off by default: **run in a new branch** ("Her çalıştırmayı yeni branch'te başlat": each run starts on a new `shotcue/…` branch) and **stash first** ("Çalıştırmadan önce değişiklikleri stash'le": uncommitted changes are stashed before the run). Turn them on in the project's settings ("Proje ayarları…").
- Runs stop at the limits set in Settings → Claude: maximum turns, a budget in USD and a timeout.
- Try Shotcue on a test repository first, before you point it at a project you care about.

## Known limitations

- The UI is in Turkish only.
- Builds are ad-hoc signed (there is no Developer ID signature), so macOS treats every update as a new app: Screen Recording and Microphone permissions are asked again after each update.
- No auto-update: download new versions from this Releases page.
- Launch at login (Settings → Genel → "Oturum açılışında başlat") can report itself as unavailable in an ad-hoc signed build. If it does, add Shotcue under System Settings → General → Login Items & Extensions instead.
